# v0.5 release gate

AgentCapDiff v0.5 is complete only when the policy model becomes more expressive without making uncertainty or policy relaxation easy to hide.

## Functional gate

- [x] Per-tool capability allowlists are enforced after global deny.
- [x] Static scope constraints distinguish allowed, broad/disallowed, and unknown scope.
- [x] Trust-boundary annotations are normalized and visible as review context.
- [x] Local inherited policies have documented deterministic precedence.
- [x] Temporary suppressions require rule ID, reason, and expiry.
- [x] Unknown constrained scope defaults to human review rather than safe/ignore.
- [x] Effective policy changes are fingerprinted separately from capability fingerprints.
- [x] PR diff output warns when effective policy becomes less restrictive.
- [x] CLI and composite Action default to `fail-on: medium`.

## Fail-closed gate

- [x] Malformed suppressions invalidate the policy.
- [x] Expired suppressions invalidate the policy instead of remaining silently active.
- [x] Absolute inherited-policy paths are rejected.
- [x] Inherited policy files must resolve inside the root policy directory.
- [x] Symlinked policy files, inheritance cycles, and excessive inheritance depth are rejected.
- [x] Unknown scope cannot become known-safe by default.

## Compatibility gate

- [x] Legacy `deny` / `require_review` / `max_risk_score` policy files remain valid.
- [x] Existing capability fingerprint semantics are unchanged by policy metadata.
- [x] Policy metadata is additive in snapshots.
- [x] Snapshots without v0.5 policy metadata remain readable.
- [x] Missing historical policy metadata does not fabricate policy-weakening warnings.

## Review UX gate

The PR summary can surface policy weakening even when capabilities do not change. The warning set covers removed denies/review requirements, raised risk thresholds, relaxed unknown handling, expanded or removed allowlists/constraints, added or extended suppressions, and removed trust-boundary annotations.

Trust-boundary annotations and active suppressions remain visible review evidence. Neither is represented as proof of runtime enforcement or safety.

## Static-analysis safety rule

All v0.5 policy work remains static and deterministic. AgentCapDiff does not execute/import target code, probe discovered endpoints, resolve runtime authorization, use credentials, or dynamically test whether a declared trust boundary is real.

A green v0.5 release gate means the documented static policy semantics and regression checks passed. It does not prove that a scanned agent is safe at runtime.
