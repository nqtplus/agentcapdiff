# v0.4 release gate

AgentCapDiff v0.4 is complete only when the capability graph remains deterministic, static, conservative, and reviewable across snapshots and pull requests.

## Verified product criteria

- versioned capability graph schema is documented and serialized deterministically
- possible data-egress paths cover credential + network, credential + email, and filesystem + email combinations
- possible supply-chain mutation paths cover source-control write + shell execution combinations
- severity and confidence remain separate signals
- broad or unknown scope cannot reduce scope-sensitive path severity
- unknown scope lowers confidence rather than being treated as safe
- snapshots persist graph data additively and older snapshots without graph data remain readable
- PR Markdown surfaces newly introduced possible paths with capability/tool evidence and conservative wording

## Safety criteria

- path detection uses only already-inferred static capability records
- no target repository code is executed or imported
- no discovered endpoint is contacted or probed
- no credentials or secrets are collected or used
- no dynamic exploitation or runtime reachability testing is performed
- findings state that runtime reachability and exploitability are not established
- absence of a path is not described as proof of safety

## Test and review gate

Required before release metadata is final:

- Ruff and pytest pass on Python 3.11, 3.12, and 3.13
- CodeQL passes
- AgentCapDiff self-policy passes
- PR capability diff passes
- project-state consistency passes
- positive, negative, ambiguous-scope, deterministic, backward-compatibility, and Markdown path tests pass

The implementation received a full green pre-release pass before final metadata was applied. Final release-state changes must receive the same full green check set before merge.
