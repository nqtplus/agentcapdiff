# v1.0 release verification record

This document maps the v1.0 stable-release gate to concrete repository evidence. It is intentionally conservative: AgentCapDiff remains a static policy aid, and passing these gates does not prove that a scanned agent is safe at runtime.

## Stable compatibility contracts

- Universal capability schema version remains `1` in `src/agentcapdiff/models.py`.
- `docs/stability-v1.0.md` defines the 1.x compatibility guarantees for capability records, policy semantics, JSON output, SARIF, snapshots, and diffs.
- `tests/test_stable_contracts_v1.py` locks the capability schema version, JSON scan top-level contract, SARIF 2.1.0 driver/result contract, source anchoring, and explicit unknown-scope semantics.
- Existing legacy/backward-compatibility coverage remains in the universal-schema, snapshot, scope, and v0.5 policy suites.

## Framework conformance

`tests/test_adapter_conformance.py` exercises equivalent serialized filesystem/network tools across:

- OpenAI API tool format
- OpenAI Agents SDK serialized format
- MCP
- Claude tool schema
- LangChain
- LangGraph-compatible metadata
- CrewAI-style metadata

The conformance gate verifies capability/risk equivalence, restricted scope equivalence, unknown dynamic scope, retained adapter provenance, and that changing framework representation cannot weaken an explicit deny decision.

This is support for static serialized metadata only. No SDK import, target-code execution, decorator invocation, live object traversal, or endpoint probing is performed.

## Semantic filesystem/network scope

Production-style regression coverage includes the main `tests/test_scopes.py` suite plus dedicated tests for:

- filesystem path widening
- network widening
- broad markers and mixed broad evidence
- unknown/dynamic scope
- no-false-expansion cases
- expansion edge cases
- multiple values and ordering
- snapshot backward compatibility
- stable capability IDs
- output model and Markdown rendering

The v1.0 contract preserves the invariant that unknown scope is uncertainty, not a safe restriction.

## Capability paths

The capability-graph and capability-path-diff suites cover possible data-egress, credential-egress, and supply-chain mutation combinations. Human-readable output explicitly says these are static evidence-backed possible paths and that runtime reachability/exploitability is not established.

v1.0 does not upgrade possible paths into exploitation claims.

## Benchmark and false-negative gate

The benchmark corpus and expected outcomes are committed under `benchmarks/`, with the release baseline in `benchmarks/baseline.json`. CI runs `python -m agentcapdiff.benchmark` and enforces the committed high-risk false-negative/parser-failure regression gate. Nuisance false positives and unknown classifications remain separately visible.

The benchmark is reproducible evidence for its committed corpus; it is not a proof of complete detection.

## Input hardening and security regressions

The full pytest suite includes deterministic fuzz/property cases, malformed/pathological JSON/YAML handling, parser limits, path traversal and symlink regressions, output-injection regressions, policy inheritance confinement, suppression expiry/fail-closed behavior, and tests that discovered endpoints do not cause network access.

Scanning remains static and must not import/execute target code, invoke discovered tools, probe discovered endpoints, or collect credentials.

## Supply-chain and release integrity

The release-integrity gate verifies reviewed exact direct dependencies, full-SHA third-party GitHub Action pins, release workflow permissions/triggers, tag/main/version integrity, SBOM generation, checksums, attestations, and immutable-release enforcement. Dependabot provides reviewable dependency/Action updates.

Production guidance uses a reviewed full commit SHA or a reviewed verified immutable release tag; floating `@main` is not a production pin.

## Vulnerability-state gate

Immediately before final v1.0 merge, the repository issue tracker must have no known unresolved critical/high AgentCapDiff vulnerability. This is a repository-known-state check, not a claim that no undiscovered vulnerability exists.

## Required final checks

The final v1.0 PR head must pass all of the following before issue closure and merge:

- CI on Python 3.11, 3.12, and 3.13
- Ruff and full pytest suite
- safety benchmark regression gate
- release-integrity regression gate
- AgentCapDiff self-policy
- PR capability diff
- Project state consistency
- CodeQL

After merge, `main` must be re-read to confirm ROADMAP, README, CHANGELOG, package/runtime version, RELEASE, SECURITY, and the merged commit all agree on v1.0 stable state.
